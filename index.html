    Github repository

    https://github.com/cinkova/fr_converbs

    The repository contains only files that serve the website https://cinkova.github.io/fr_converbs/ . I publish the materials for this website using git subtree split. The repository corresponds to the pages subfolder of myproject_olgaN_converba.

    ImportantCommitting and pushing to the https://cinkova.github.io/fr_converbs/ github repository

    • Do not use the buttons in RStudio. Instead, run this sequence of commands from the terminal (linux, MINGW64): navigate to the folder myproject_olgaN_converba. From there call this:

      git add pages
git commit -m "my new message blablabla"
git subtree split -P pages -b pages-publish
git push origin pages-publish:main

      The third line creates a disposable temporary branch called pages-publish (arbitrary name). The fourth line (pushing) says exactly: “Push whatever commit pages-publish points to, but call it main on the remote.” After pushing is completed, delete the temporary branch:

      git branch -D pages-publish

    • Never do: git init (or, for that matter, anything git) inside pages. 💀 If you accidentally do, remove the fresh .git and .gitignore items from pages.

    • What this correct sequence actually does is calling a git helper called subtree. This module records changes in the entire parent repository (this is desirable) and extracts pages as a standalone history from this record. It publishes only the changes that happened inside the pages folder.

    Source file to generate reports, intermediate data files, and plots

    The most important file in this setup is the Quarto markdown file myproject_olgaN_converba\01_translMining_pokus.qmd. It contains a script that I originally made for French. You can either run it chunk by chunk, or Render it. The output format options encoded in its YAML header are static html and pdf. Every time you run the file, no matter in which regime, it generates a folder with files. The names of these items encode the target language and contain a random sequence of numbers and letters to prevent overwriting by the next run.

    At first, the target language was only French, but later other languages were required, so I added parameters in the YAML header to enable switching of the target language.

    I have made a copy of it for each language under scrutiny.

    Run it in RStudio or in the terminal. My workflow in terminal (linux) would go like this:

    quarto render TranslationMining_French.qmd --to html --output-dir pages/html --output French_full_report.html

    But you can as well take any of these qmd files and run them with new parameters from the command line. The syntax goes like so:

    quarto render TranslationMining_French.qmd \
  --to html \
  --output-dir pages/html \
  --output French_full_report.html \
  -P language_in_focus:French \
  -P input_file:Analyses_v2_SC.xlsx \
  -P target_form_column:form.fr \
  -P row_id_column:ID_occurrence \
  -P target_kwic_column:fr

    This will produce pages/html/French_full_report.html This would be one of the files you see in the language tabs above.

    These are parameters for English (and basically for all non-French languages in the original input file):

    params:
  input_file: "Analyses_v2_SC.xlsx"
  language_in_focus: "English"
  target_form_column: "form.en"
  row_id_column: "ID_occurrence"
  target_left_kwic_column: NULL
  target_kwic_column: "en"
  target_right_kwic_column: NULL
  target_lemma: NULL

    How to say null in the command line:

    -P target_left_kwic_column:null

    and strings with spaces must be quoted (just in case):

    -P language_in_focus:"Old French"

    When rendered in RStudio, the html/pdf output will always have the same name and will be placed in the same folder as the source and you will have to rename it and move to the pages/html or pages/pdf folder manually.

    Other files generated by the source file

    Besides generating a report in html or pdf, each run of the file generates:

    • a folder in myproject_olgaN_converba with a unique name (e.g. French_OX37K or Russian_0RBB4)

      • and within this folder:

        • static semantic map plot in three different formats (pdf, png, and svg)

        • a matrix with the Hamming distances (agreement = 0, disagreement = 1) between observations, based on the values in their corresponding form columns: distance_matrix.csv (it is a csv2 file).

        • a matrix with the Euclidean (?) distances created by the stats::cmdscale command (default setting, 2 dimensions): mds_result.csv (also actually a csv2 file).

        • a tsv file with the following columns:

          • ID_occurrence

          • src.lang

          • the concordance column for the given target language, e.g. cs. , or the three columns fr1, KWIC.fr, fr2 for French.

          • form.fr

          • form.cs

          • form.en

          • form.es

          • form.it

          • form.pl

          • form.ru

          • dimension1

          • dimension2

        • the dynamic plot created by plotly in pages. It consists of a html file and a folder with the same name and _files suffix, e.g. Polish-SLD6U_offline_interactive_plot.html and Polish-SLD6U_offline_interactive_plot_files. It always shows all data points and their distribution in the two-dimensional space of the multidimensional scaling. The legend lists all forms the data points had in the given target language. The plot is further subdivided in facets (subplots) according to the target language of the given sentence. Polish is missing because there are no documents in the sample with Polish as the source language. This also means that all Polish sentences come from translations.

    Different concordance structure for some languages

    The input file (“Analyses_v2_SC.xlsx”) has a slightly different structure of French columns from other languages’ columns. The concordance consists of “fr1”, “KWIC.fr”, “fr2”, whereas the concordances of other languages are not separated into left and right context and KWIC. The corresponding columns are called with the abbreviated name of the given language, e.g. ru, es, pl, cs, it, en.

    File clutter when you render one language file several times

    To generate a html and a pdf from one source, you have to run render on the source two times. Every time you get a new folder with the tables and a new dynamic plot. The advantage of it is that you can keep track of possible changes due to different versions of the input xlsx file or that you have experimented with something inside the source file. The disadvantage is clutter if you only need one set for each language. Deal with it manually. And mind to link from index to the exact file name (the target language and random sequence must be identical in the link and the file name!)

    All Polish texts come from translations

    This could be a problem in future modeling when we model the influence of being an original/ a translation. We might have to disregard the Polish data in that experiment.
